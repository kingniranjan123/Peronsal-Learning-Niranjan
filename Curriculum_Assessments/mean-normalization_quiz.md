# Mean Normalization Quiz

## Part 1: True/False Questions (10 Questions)

1. **Question:** Setting `withMean=true` on a `StandardScaler` applied to a dataset containing highly sparse `VectorUDT` columns will preserve the memory footprint per row as long as Tungsten Whole-Stage CodeGen (WSCG) is active.
**Answer:** False
**Mastery Explanation:** Setting `withMean=true` on sparse data causes structural densification. Every 0.0 becomes (0.0 - mean), forcing Spark to cast `SparseVector` to `DenseVector`. WSCG does not prevent this memory explosion, which often leads to OOM errors.

2. **Question:** Catalyst optimizes the statistical aggregation phase of mean normalization by utilizing Welford's online algorithm to compute global variance and mean in a single distributed pass.
**Answer:** True
**Mastery Explanation:** Welford's algorithm is numerically stable and allows Spark to compute both running mean and variance without floating-point cancellation errors in a single pass over the RDD/DataFrame.

3. **Question:** During the transformation phase of `StandardScaler`, Spark relies on standard Java serialization to broadcast the computed mean vectors to the worker nodes by default, unless explicitly overridden.
**Answer:** False
**Mastery Explanation:** Spark relies on the TorrentBroadcast protocol to distribute the means. While Kryo is highly recommended, TorrentBroadcast itself is the peer-to-peer distribution mechanism, and for MLlib objects, Spark often leverages its internal serialization optimizations.

4. **Question:** Extracting the global mean of a scalar column into a driver-side Row and injecting it back into a DataFrame via the `lit()` function avoids the need for explicit broadcast variables during normalization.
**Answer:** True
**Mastery Explanation:** Injecting a literal via `lit()` embeds the value directly into the Catalyst Abstract Syntax Tree (AST). Tungsten WSCG then hardcodes this value into the generated Java bytecode, completely bypassing broadcast variables.

5. **Question:** When `spark.driver.maxResultSize` is exceeded during the `fit()` phase of a `StandardScaler` on a 50-million-dimension dataset, Spark automatically falls back to a Disk-based Aggregate strategy.
**Answer:** False
**Mastery Explanation:** There is no automatic fallback to disk for driver results. If the aggregated mean vector collected to the driver exceeds `spark.driver.maxResultSize`, the job will crash instantly with an exception.

6. **Question:** The computational complexity of the Vector Transformation phase in Spark MLlib's mean normalization requires a distributed shuffle across all partitions.
**Answer:** False
**Mastery Explanation:** The Vector Transformation phase is purely a map-side operation (O(N * D)) and requires no shuffle. The shuffle (Reduce) only occurs during the Statistics Aggregation phase.

7. **Question:** When dealing with sparse data (like TF-IDF output), a senior engineer should use `MaxAbsScaler` or only set `withStd=true` on `StandardScaler` to avoid JVM heap exhaustion.
**Answer:** True
**Mastery Explanation:** `MaxAbsScaler` divides by the maximum absolute value without shifting the mean, preserving structural zeros. Similarly, scaling only by variance (`withStd=true`) preserves sparsity.

8. **Question:** Tungsten uses Unsafe memory operations to read vector elements directly from Parquet off-heap memory, minimizing Garbage Collection (GC) pressure during the mean subtraction phase.
**Answer:** True
**Mastery Explanation:** Tungsten bypasses the JVM heap by operating directly on binary data in off-heap memory. This prevents the instantiation of millions of short-lived Java objects and drastically reduces GC overhead.

9. **Question:** A `HashAggregateExec` strategy is always chosen by Catalyst for the partial aggregation step, regardless of the feature dimension size or memory constraints.
**Answer:** False
**Mastery Explanation:** Catalyst will fall back to a `SortAggregateExec` if memory is constrained or if the aggregation state becomes too large, though `HashAggregateExec` is preferred when memory permits.

10. **Question:** Increasing `spark.kryoserializer.buffer.max` is a valid mitigation strategy when broadcasting extremely high-dimensional mean vectors that exceed 64MB.
**Answer:** True
**Mastery Explanation:** The default Kryo buffer limit is 64MB. Massive dimensional vectors require increasing this buffer size to prevent buffer overflow exceptions during the serialization of the broadcast variable.

42. **Question:** **Identify the Optimizer Blocker:**
```scala
val meanVal = df.select(avg("colA")).first().getDouble(0)
val normalizedDF = df.rdd.map(row => {
  val newVal = row.getAs[Double]("colA") - meanVal
  Row(newVal)
})
```
**Why is this approach inferior to `df.withColumn("norm", col("colA") - lit(meanVal))`?**
**Answer & Mastery Explanation:** Dropping down to the `rdd.map` API acts as an **Optimizer Blocker**. Catalyst cannot inspect the logic inside the Scala closure. Consequently, Tungsten cannot perform Whole-Stage CodeGen (WSCG). The `withColumn` + `lit()` approach keeps the operation in the logical plan, allowing Tungsten to fuse the subtraction into a highly optimized, GC-free loop.

The optimization is to use `StorageLevel.MEMORY_ONLY_SER` combined with Kryo serialization to store the vectors as contiguous off-heap/byte-array memory, bypassing the Garbage Collector.
